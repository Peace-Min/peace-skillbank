# AddSIM XML 분석 보고서 스킬

AddSIM의 BSM/플레이어/컴포넌트 XML 정의 파일을 분석해 **항상 동일한 포맷**의 자립형(self-contained) HTML 보고서를 만든다.

## 핵심 원칙 — 왜 이렇게 하는가

이 스킬이 존재하는 이유: LLM이 XML을 직접 읽고 매번 자유롭게 분석하면 (1) 뎁쓰(계층) 정보가 누락되고 (2) 파일마다/호출마다 포맷이 달라져 사용자가 결과를 신뢰할 수 없다.

그래서 역할을 엄격히 나눈다:

- **구조 추출, 계층 정리, 속성 수집, 통계, HTML 생성** → 전부 `scripts/Analyze-AddsimXml.ps1`이 결정적으로 수행한다. 절대 직접 하지 않는다.
- **모델(너)의 역할은 두 가지뿐**: ① 스크립트 실행과 결과 안내, ② 보고서의 "문서 해석" 섹션에 들어갈 요약문 작성.
- **생성된 HTML을 직접 수정하지 않는다.** 재실행하면 사라진다. 보고서를 바꾸고 싶으면 스크립트나 매핑(config/mapping.json)을 바꾼다.
- 보고서의 수치("요소 137개, 최대 뎁쓰 4" 등)는 스크립트가 계산한 값만 사용한다. 네가 세거나 추정한 숫자를 쓰지 않는다.

## 실행 환경

- Windows + PowerShell 5.1 이상. 외부 모듈/인터넷 불필요.
- 실행이 막히면: `powershell -NoProfile -ExecutionPolicy Bypass -File <스크립트> ...`

## 워크플로

사용자가 `/addsim-xml-report <경로>` 형태로 호출하거나 파일을 @멘션하면 그 경로가 1단계의 `-Path` 인자다. 경로 없이 "xml 분석해줘"라고만 하면 대상 파일/폴더 경로를 먼저 확인한다. 별도 요청이 없어도 1~3단계(분석 → 요약 작성 → 요약 주입)를 기본으로 끝까지 수행한다.

### 1단계 — 분석 스크립트 실행

```
powershell -NoProfile -ExecutionPolicy Bypass -File "<스킬경로>\scripts\Analyze-AddsimXml.ps1" -Path "<XML파일 또는 폴더>" -OutDir "<출력폴더>"
```

주요 파라미터:

| 파라미터 | 기본값 | 설명 |
|---|---|---|
| `-Path` | (필수) | XML 파일 하나 또는 폴더. 폴더면 내부 *.xml 전부 처리 |
| `-OutDir` | `.\xml-reports` | 보고서 출력 폴더 |
| `-Recurse` | 꺼짐 | 폴더의 하위 폴더까지 처리 |
| `-MappingPath` | `<스킬>\config\mapping.json` | 요소 한글 라벨/커넥션 매핑 파일 |
| `-SummaryFile` | 없음 | 3단계에서 사용. "문서 해석" 섹션에 주입할 텍스트 파일 |
| `-OpenDepth` | 3 | 트리에서 이 뎁쓰까지 펼쳐서 표시 |
| `-MaxTableRows` | 300 | 속성 상세 표의 요소별 최대 행 수(초과분은 표에 생략 건수 명시, 트리에는 전부 표시됨) |

파일마다 두 가지가 생성된다:

- `<이름>.report.html` — 완성된 보고서 (요약 섹션은 아직 placeholder)
- `<이름>.data.json` — 분석 다이제스트 (2단계에서 네가 읽을 파일)

폴더 처리 시 `index.html`(전체 목록)도 생성된다. 콘솔에는 파일별 통계와 **미분류 요소 목록**이 출력된다.

### 2단계 — 요약문 작성 (digest 기반)

`<이름>.data.json`을 읽고 "문서 해석" 요약문을 텍스트 파일로 작성한다(예: `<이름>.summary.txt`, UTF-8). 문단 구분은 빈 줄.

작성 규칙:

- **근거는 data.json만 사용한다.** 원본 XML 전체를 컨텍스트에 로드하지 않는다(대용량일 수 있고, 스크립트가 이미 전수 추출했으므로 다시 읽으면 편향과 낭비만 생긴다). 특정 값 확인이 꼭 필요하면 digest의 인스턴스 경로를 근거로 해당 부분만 확인한다.
- 수치는 digest의 값을 그대로 인용한다.
- 문서 유형(BSM/플레이어/컴포넌트), 전체 규모, 계층 구성의 특징, 핵심 요소들, 커넥션 관계, 특이사항(비어있는 섹션, 미분류 요소 등) 순으로 5~12문장, 한국어로 쓴다.
- AddSIM 도메인 배경지식이 필요하면 `references/addsim-structure.md`를 읽어 활용한다. 단, 그 문서는 공개 논문 기반이므로 실제 파일 내용과 다르면 **파일 쪽을 사실로 삼는다**.
- 확실하지 않은 해석에는 문장에 "…로 추정된다"를 명시한다. 이 섹션은 보고서에서 "모델 생성" 배지가 붙어 추출 데이터와 구분된다.

### 3단계 — 요약 주입 재실행

```
powershell -NoProfile -ExecutionPolicy Bypass -File "...\Analyze-AddsimXml.ps1" -Path "<XML파일>" -OutDir "<출력폴더>" -SummaryFile "<이름>.summary.txt"
```

같은 입력이면 보고서는 요약 섹션만 채워진 동일 결과가 재생성된다(멱등). `-SummaryFile`은 단일 파일 처리에서만 유효하다. 여러 파일이면 파일별로 반복한다.

### 4단계 — 매핑 캘리브레이션 (신뢰성의 핵심)

콘솔과 보고서의 "요소 인벤토리" 섹션에 **미분류 요소**(매핑에 없는 요소명)가 나열된다. 이것은 오류가 아니라 캘리브레이션 신호다:

1. 미분류 요소 목록을 사용자에게 보여준다.
2. 사용자에게 각 요소의 한글 라벨(및 선택적 설명)을 확인받는다.
3. 확정된 것만 `config/mapping.json`의 `labels`에 추가한다. 커넥션(연결 관계) 성격의 요소면 `connectionNames`에, 연결의 출발/도착을 나타내는 속성명이면 `endpointAttrNames`에 추가한다.
4. 재실행하면 해당 요소들이 라벨과 함께 표시된다.

이 과정을 몇 번 거치면 매핑이 현장의 실제 AddSIM 스키마에 수렴한다. **모르는 요소를 임의로 라벨링해서 매핑에 넣지 않는다** — 사용자 확인이 없으면 미분류로 남겨두는 것이 옳다(빠짐없이 표시는 되므로 정보 손실은 없다).

## 보고서 구성 (고정 포맷)

모든 보고서는 같은 순서의 섹션을 가진다: ① 파일 정보(SHA-256 해시 포함) → ② 검증 요약(파싱/렌더링 요소 수 일치 여부, 최대 뎁쓰, 속성 수 등) → ③ 계층 구조 트리(뎁쓰 배지, 접이식) → ④ 뎁쓰별 요소 요약 → ⑤ 요소별 속성 상세 → ⑥ 커넥션 → ⑦ 요소 인벤토리·매핑 상태 → ⑧ 문서 해석(모델 생성 배지). **모델의 해석/판단은 항상 마지막 섹션**이다 — 기계 추출 사실(1~7)을 먼저 보여주고 의견(8)을 뒤에 두어야 독자가 사실과 판단을 구분해 신뢰할 수 있다. 외부 리소스(CDN, 웹폰트) 없이 단일 파일로 열린다.

사용자에게 결과를 전달할 때는: 보고서 경로, 검증 요약 수치(요소 수/최대 뎁쓰/일치 여부), 미분류 요소 유무를 함께 알린다.

## 문제 해결

- **XML 파싱 실패**: 보고서 대신 콘솔과 index.html에 오류로 기록된다. 원인은 대개 잘못된 XML(태그 미닫힘)이거나 인코딩 선언 불일치. 파일 앞부분 몇 줄만 확인해 사용자에게 알린다. 임의로 파일을 고쳐서 재시도하지 않는다(원본 훼손 금지 — 사본을 만들어 고칠지는 사용자가 결정).
- **한글 깨짐**: XML 선언의 encoding과 실제 인코딩이 다른 경우다. 사용자에게 원본 인코딩을 확인한다.
- **보고서가 너무 클 때**: `-OpenDepth 1`로 트리를 접고, `-MaxTableRows`를 줄인다. 트리는 어떤 경우에도 전체 요소를 포함한다.
- **DTD 참조가 있는 XML**: 보안상 DTD/외부 엔티티는 무시하도록 설정되어 있다(폐쇄망 보안 원칙). 엔티티 치환이 필요한 파일이면 사용자와 상의한다.

## 파일 안내

- `scripts/Analyze-AddsimXml.ps1` — 분석·보고서 생성 스크립트 (전부 여기서 수행)
- `config/mapping.json` — 요소 라벨/문서유형/커넥션 매핑 (현장에서 보강하는 파일)
- `references/addsim-structure.md` — AddSIM 공개 배경지식 (요약 작성 시 참고, 실제 파일이 우선)
- `assets/samples/` — 반입 후 자가 테스트용 합성 샘플 XML 3종 (실제 AddSIM 데이터 아님)

반입 직후에는 `assets/samples/`로 스킬 자가 테스트를 한 번 실행해 환경 호환성을 확인하는 것이 좋다.
