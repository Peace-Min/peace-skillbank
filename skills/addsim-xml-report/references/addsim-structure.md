# AddSIM 배경지식 (공개 논문 기반)

> 주의: 이 문서는 공개 학술자료(WSC 2014, Defence Science Journal 2012, 한국군사과학기술학회지 2021 등)에서 정리한 배경지식이다.
> **실제 분석 대상 XML의 내용과 다르면 항상 파일 쪽을 사실로 삼는다.** 요약문에 이 지식을 사용할 때 파일에서 직접 확인되지 않은 내용이면 "공개 자료 기준" 또는 "추정"임을 명시한다.

## AddSIM 개요

- AddSIM(Adaptive distributed parallel Simulation environment for Interoperable and reusable Models)은 국방과학연구소(ADD)가 개발한 컴포넌트 기반 무기체계 통합 시뮬레이션 환경.
- 고해상도 공학급 모델로 교전급 시뮬레이션을 수행하여 무기체계 성능지표(MOP)/효과도(MOE)를 분석.
- 4대 구성: 사용자 인터페이스(모델 편집·시나리오·분석 도구 + 자원 저장소), 시뮬레이션 엔진(커널), 외부 인터페이스(C/C++, MATLAB, HLA/RTI, DIS), 지원 서비스(지형·대기·해양 환경, 공간정보, 저널링, 유틸리티).
- 커널은 연속시간 + 이산사건 하이브리드 스케줄링. 분산은 TAO-CORBA 기반(이후 DDS 연구), 병렬 시간동기화는 BTB 계열.
- 버전: v1.0(2009~2011) → v2.0(2014, 모델 계층화·표준 인터페이스) → v3.0(BSM 표준 라이브러리 21종 포함).

## 플레이어 (Player)

- 시뮬레이션 모델의 최상위 컴포넌트. 보통 무기체계 1개(전차, 항공기, 미사일, 함정, 레이다 등)를 표현.
- 계층: 시뮬레이션 모델 → 플레이어들 → 컴포넌트들 → 하위 컴포넌트(재귀).
- 플레이어 간 통신: ① 공간정보 서비스(위치·속도·RCS 등을 공간 DB에 갱신/조회), ② 직접 연결 인터페이스(표적정보, 발사명령 등 메시지).

## BSM (Base System Model, 기본체계모델)

- 무기체계 모델의 표준 아키텍처(참조 구조). 플레이어를 규격화된 형태로 만들기 위한 틀.
- 3대 구성:
  - 공유데이터: 정보(타 모델로부터 수신), 파라미터(고정 특성), 속성(시뮬레이션 중 변하는 상태변수)
  - 물리 컴포넌트: 기동, 탐지, 통신 등 물리적 거동·기능
  - 논리 컴포넌트: 교전수칙, 운용자 의사결정 논리(DEVS 기반 계층적 모델링 사례 있음)
- 한국군 주요 무기체계 대상 21종 BSM이 표준 라이브러리로 개발됨(지상/해상/공중/미사일 등).

## 컴포넌트 (Component)

- 플레이어(또는 상위 컴포넌트)를 구성하는 기능 단위 빌딩블록. 특정 기능을 독립 수행.
- DLL로 컴파일되어 plug-in & play 방식으로 동적 로딩. 구성·통신·제어 메타정보는 XML로 기술되며 커널이 실행 시 해석.
- 공통 메타모델이 컴포넌트–플레이어–인터페이스–멤버함수–변수–데이터타입 관계를 정의.
- 인터페이스: 컴포넌트/플레이어 간 이벤트 통로.

## 요약문 작성 시 활용 예

- 문서 유형이 "컴포넌트 정의"이고 Connection 요소가 많다면: "컴포넌트 간 이벤트 통로(인터페이스/커넥션) 정의가 문서의 중심으로 추정된다" 식으로 연결.
- BSM 문서에서 SharedData/Physical/Logical 계열 요소가 보이면 공개 자료의 3대 구성과 대응시켜 설명 가능(단, 요소명이 다르면 파일 기준으로 서술).
