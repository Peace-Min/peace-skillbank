# 단위 시험 분류와 입력·골든 형식

기대값은 **C# 원본을 실행해서** 얻는다. LLM이 기대값을 쓰지 않는다. 너(LLM)의 일은 메서드 분류와 **입력 목록** 작성이다. 입력이 엉성해도 정답은 C#이 만들므로 결과가 틀리지는 않고 범위만 줄어든다.

## 1. 메서드 분류

| 분류 | 판별 (하나라도 해당) | 시험 |
|---|---|---|
| **순수** | 인자와 반환값만으로 결과가 정해짐: 산술·형변환·비트 연산, 파싱·서식, 값에 따른 분기, 컬렉션 순회·검색·정렬, 직렬화 `Write`/`Read`, 예외를 던지는 검증 | **메서드 단위 필수.** 정상·경계·오류 입력 |
| **상태** | 객체 필드를 바꾸거나 필드에 따라 결과가 달라짐 (위 판별 중 하나 이상 포함) | **객체 시나리오.** 생성 → 공개 메서드 호출 순서 → 공개 상태 비교. 공개 메서드는 모두 최소 1회 |
| **연결** | 소켓·스레드·타이머를 다루거나 다른 객체 호출만 이어 줌 | 단위 시험 없음 (연동 시험에서) |
| **불필요** | 필드 대입만 하는 setter, 필드 반환만 하는 getter, 한 줄 위임, 필드 초기화만 하는 생성자 | 없음 |

private 메서드는 분류하지 않는다(공개 메서드를 통해 검증).

## 2. 입력 목록 형식

포팅 보고의 "시험 분류" 표에 메서드마다 입력을 적는다. 사람이 이 형식 그대로 C# 기록기 입력 파일(`<프로젝트>.cases`)에 모은다.

```text
@method Namespace.Class.Method
@args int32 string
case  12 | "abc"            # 정상
case  0 | ""                # 경계: 0, 빈 문자열
case  -2147483648 | "가나"  # 경계: 최소값, 한글
case  1 | null              # 오류: null
```

```text
@scenario Namespace.Class ModeTransition
new   ()
call  SetMode | 1
call  Start
check GetMode GetIsRunning      # 공개 상태 읽기
call  Stop
check GetMode GetIsRunning
```

값 표기:

| 형식 | 표기 |
|---|---|
| 정수 | 10진 (`-5`, `255`) |
| 실수 | 왕복 형식 `R` 문자열 (`0.1`, `-1E+300`), 특수값 `NaN`, `Infinity`, `-Infinity` |
| bool | `true` / `false` |
| 문자열 | `"..."` (JSON 이스케이프), `null` |
| 바이트 배열 | `b:0A0BFF`, 빈 배열 `b:` |
| 열거형 | 정수 값 |
| 목록 | `[1, 2, 3]` |

## 3. 골든 파일 형식 (C# 기록기가 생성)

```text
@method Namespace.Class.Method
case 1  ret=15 out=- ex=-
case 2  ret=0 out=- ex=-
case 4  ret=- out=- ex=System.ArgumentNullException
```

- `ex`는 C# 예외 형식 전체 이름. C++ 재생기는 같은 이름의 `NetCompat` 예외인지 확인한다.
- 골든은 **x64 프로세스**로 기록한다(`Prefer32Bit` 끔). 32비트 JIT은 실수 계산 결과가 다를 수 있다.
- 실수는 비트까지 같아야 통과. 수학 함수(`Sin`, `Pow` 등)를 거친 값만 사람이 정한 허용 오차를 둔다.
- 시각·난수·순서가 실행마다 바뀌는 메서드는 C#을 두 번 기록해 같은지 먼저 확인한다. 다르면 그 메서드는 단위 시험에서 뺀다.

C# 기록기와 C++ 재생기는 별도 도구다. 이 스킬은 입력 목록만 만든다.
